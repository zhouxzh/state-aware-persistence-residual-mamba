## 1. 研究目标与边界

本研究检验一个有限、可证伪的问题：在只使用预测原点及其过去信息的条件下，状态感知的
学习型残差修正，能否在预先定义的变化状态中改善持久性预测，同时不在稳定状态中造成
实质性损失。研究对象是单变量目标历史预测（S-only），不是交易策略、市场有效性、
普适的分布漂移处理器或跨领域 SOTA 排行榜。

候选预测形式为

\[
\widehat{\mathbf y}_{t+1:t+H}=\mathbf b_t+g_t\,\mathbf r_t,
\qquad \mathbf b_t=x_t\mathbf 1_H,
\]

其中 \(\mathbf b_t\) 是持久性基线，\(\mathbf r_t\) 是从因果历史中学习的变化残差，
\(g_t\in(0,1)\) 是状态门。所有状态特征和门值只能由原点 \(t\) 及其之前的历史计算。

本计划的核心是新的合成与公开真实数据实验。历史金融 `financial_s_only_v1/v2` 仅保留为
旧研究审计材料，绝不用于选择新模型、新数据、阈值、超参数或有利的报告口径。严禁读取、
复制或混入 `~/Documents/Self-Supervised-Contrastive-Forecsating` 及其中的 PEMS、Weather、
METR-LA、PEMS-BAY、AutoCon、表示融合代码或任何结果。新的真实数据从公开原始来源重新
取得并记录许可证、下载时间和哈希。

## 4. 冻结的模型族与公平比较

每个学习模型使用相同的 S-only 历史输入、训练/验证切分、最大预测跨度、随机种子、训练
样本抽取、早停准则、搜索预算、混合精度设置和 GPU 配额。所有模型输出最大跨度
`H_max` 的路径；短跨度只评估同一路径的前缀，不为有利跨度另训模型。

| ID | 形式 | 作用 |
| --- | --- | --- |
| M0 | `b_t = x_t 1_H` | 强且透明的持久性基线。 |
| M1 | `b_t + r_linear(history, phi_t)` | 线性变化残差；检验是否只需简单校正。 |
| M2 | `b_t + r_mamba(history, phi_t)`，固定 `g=1` | 无门控 Mamba 残差；H1 的主要比较对象。 |
| M3 | `b_t + g(phi_t, h_t) r_mamba(history, phi_t)` | 状态感知门控 Mamba 残差；H2 的主要比较对象。 |
| M3-shuffle | 与 M3 相同，但在训练和推理中按预先固定的独立置换打乱 `phi_t` 与历史的配对 | 次要容量/状态信息对照；只报告预定义对照结果。 |

其中 `h_t` 是 Mamba 对当前历史的汇聚表示。M2 与 M3 必须共享残差编码器宽度、深度、状态
维度、dropout、优化器和训练预算；M2 也接收同一 `phi_t` 作为残差编码输入。M3 唯一新增的
预测通路是标量门 `g_t`。门网络的少量额外参数、以及 M3-shuffle 的含义必须在方法中如实
说明，因此 M3--M2 是严格的预注册式消融/完整配方比较，不自动证明单独的标量门有因果效应。

门的初版固定为单一标量

\[
g_t=\sigma\{a(\phi_t)+c(h_t)\},
\]

并逐元素缩放整个残差路径。主协议中不使用根据测试表现选择的门惩罚；若实现稳定性正则，
其系数必须在 `protocol.lock.json` 中固定，主分析不得在结果后修改。M1 的线性映射、M2/M3
的残差头和参数量均须在配置中显式导出。

为避免只和弱参考比较，真实数据还报告以下预先指定的上下文基线：季节性朴素法（仅在
预先定义季节周期 `P` 可用时）、漂移法、固定候选集并仅在验证集选择的 ETS/ARIMA，以及
DLinear。任何 PatchTST 或其他深度模型只能作为次要、同预算上下文比较，不能取代 M0--M3
的主要配对检验。统计模型的搜索空间、失败回退规则及计算上限在协议中冻结。

## 5. 因果状态特征与状态标签

对每个原点，先仅用输入窗口 `x_{t-L+1:t}` 计算 `phi_t`。冻结的初版包含：

1. 最新水平相对窗口稳健中位数的 z 分数；
2. 最新一阶差分和二阶差分的稳健标准化值；
3. 短/中/长窗口的最小二乘趋势斜率；
4. 短期波动与长期波动的比值；
5. 短窗口中最大绝对标准化跳变；
6. 若已在数据配置中指定季节周期，当前水平相对同相位历史值的偏离。

固定窗口为 `W_short=P/4`、`W_mid=P`、`W_long=4P=L`，所有分母采用仅来自输入窗口的
MAD/标准差并加上固定 `epsilon`。不足窗口、常数序列和缺失值的处理要写入单元测试。模型
不得接收潜在真实机制标签；合成机制标签只用于评估分层。

真实数据的状态层使用冻结的、仅由 `phi_t` 派生的 `stable`、`change` 二元规则。阈值必须在
合成训练/验证阶段或独立开发数据上一次性确定，并写入配置；不得在真实测试集、门值、误差
或显著性结果后改动。除主二元层外，原始连续状态分数、每个特征和所有无资格原点均须保存，
使后续审计能够发现阈值敏感性。

## 6. 合成实验：主要机制证据

### 6.1 生成器

合成序列由具有 AR 创新、局部线性趋势与可选季节项的基础过程生成；变化在隐藏机制层注入。
模型只能观察生成后的单变量序列。每条序列长度固定为 `T=2048`，输入长度 `L=384`，最大
预测跨度 `H_max=96`，评估前缀为 `H={12,24,48,96}`。训练、验证和测试按**独立生成的序列**
切分，而非把同一序列的高度重叠原点误作独立样本。

机制、强度、持续时间、变点位置、基础 AR 系数、趋势、季节幅度和噪声种子由已冻结的
`configs/sapr_mamba_v1/synthetic.json` 控制。变化强度相对于该序列训练段的创新标准差定义，
不得按模型误差重新标定。

| 层 | 机制 | 三个预设强度/幅度 | 作用 |
| --- | --- | --- | --- |
| 对照 | 稳定 AR-趋势-季节过程 | 基准参数三档 | 检验稳定状态安全性。 |
| A | 均值/水平跳变 | 0.5、1.0、2.0 个创新标准差 | 检验突变后持久性是否已足够。 |
| B | 趋势折点 | 在 96 步累计产生 0.5、1.0、2.0 个标准差偏移 | 检验持续变化的残差校正。 |
| C | 方差转换 | 创新标准差乘数 1.5、2.0、3.0 | 检验风险状态，不预设一定会提高点预测。 |
| D | 渐进漂移 | 在 96 步内累计 0.5、1.0、2.0 个标准差偏移 | 检验可从已观察轨迹外推的变化。 |
| E | 季节幅度/相位变化 | 0.5、1.0、2.0 个季节幅度单位 | 检验周期结构正在变化时的稳健性。 |

每个非稳定机制--强度单元生成 200/50/100 条训练/验证/测试序列；稳定对照生成
300/100/200 条。总计为 3300 条训练、850 条验证和 1700 条测试独立序列。每条测试序列
按冻结的、非重叠或间隔至少 `H_max` 的预测原点聚合为一个序列--跨度损失，因而该序列而非
窗口成为主要推断单位。变点位置由生成器分层抽样，且所有评估的 `change` 原点都已经具有
可观测的历史状态信号；对完全不可预测的未来突发跳变单独标记为压力对照，不把它混入对
“状态感知”能力的主要检验。

### 6.2 合成分析

主要合成终点是在全部非稳定机制和强度等权汇总后的序列级路径 RMSE；路径 MAE 为共同主要
稳健性终点。对 H1 计算 `loss(M2)-loss(M1)`，对 H2 计算 `loss(M3)-loss(M2)`，负值有利于
前者。稳定状态安全终点为 M3 相对 M0 的序列级相对 RMSE 差；预定义容忍边界为 `+2%`。
这不是“证明相等”，而是一个透明的实际劣化界限。

置信区间通过 10,000 次配对、按独立测试序列重采样的 percentile bootstrap 得到。主要家族为
H1、H2 和稳定安全性在四个跨度上的 12 个比较，使用 Holm 校正。机制--强度细分、MAE、
M3-shuffle 和单一状态特征均为预先规定的次要/描述性分析，完整表格照常发布，不以某一
显著单元替代主要汇总。

## 8. 指标、统计和门控证据

### 8.1 预测误差

每个序列--跨度单元首先在原始目标尺度上计算路径 MAE 与 RMSE。跨量纲等权汇总时仅追加：

\[
\mathrm{sMAE}=\frac{\mathrm{path\ MAE}}{SD_{train}},\qquad
\mathrm{sRMSE}=\frac{\mathrm{path\ RMSE}}{SD_{train}},
\]

其中 `SD_train` 是该序列训练段水平值的总体标准差（`ddof=0`）。RMSSE 不作为本研究的主要
指标、主要排名或假设检验分母。每个表都显示样本单位、是否原始尺度、是否标准化以及聚合
权重；不把不同目标单位的原始 RMSE 直接平均。

真实数据主要表按“域内先对序列等权，再对三个来源域等权”的两层规则汇总。所有域--序列--
状态--跨度--种子--模型单元须在结果矩阵中保留。由于真实来源簇数量很少，跨域推断以效应
大小、来源分层和簇内配对区间为主，不能把同一来源的许多滚动窗口伪装成独立样本，也不以
一个总 p 值宣称普适结论。

### 8.2 不确定性、比较族与缺失

合成测试以独立序列为重采样单位；真实数据以序列为单位并在来源域内分层重采样。对每个
主要差异保存点估计、95% CI、有效序列数、失败单元数和 Holm 校正后的 p 值。所有随机模型
的五个种子都报告，模型间比较首先在同一数据/原点上配对，再按种子平均为该序列单元；不能
把同一序列的种子和重叠原点重复计为独立样本。

训练失败、OOM、NaN、缺失预测、统计模型不收敛和数据质量排除必须写入 `failures.csv`。
禁止自动“成功重跑直到好看”；允许一次固定的技术重试（相同配置、相同种子），第二次失败
后保留失败状态，并在完成矩阵中显示。若某个主比较缺少预定单元，主结论标为不完整，而不是
缩小分母。

### 8.3 描述性门控审计

对 M3 的每个测试原点保存 `g_t`、`||r_t||`、完整 `phi_t`、状态标签、预测与目标。预定义的
描述性检查是：

1. `change` 与 `stable` 分层中的门值分布及中位数差；
2. 每个序列内 `g_t` 与连续变化分数的 Spearman 相关；
3. 每个序列内 `g_t` 与残差路径范数的 Spearman 相关；
4. M3 与 M3-shuffle 的同一误差矩阵对照。

这些分析不能用来反向定义状态，也不能被解释为门值导致了精度变化。所有门值接近 0 或 1、
高方差、与状态无关或与误差不一致的模式均应如实保留。

向量、门轨迹、检查点和 TensorBoard 文件放在 `results/` 或已核验的外部归档，不提交普通 Git。
紧凑冻结 release 至少含：

- `protocol.lock.json`、环境清单、Git 提交与 dirty 状态；
- 数据来源、实体、切分、原始/处理文件 SHA-256 及有效原点清单；
- 全部模型--域--序列--状态--跨度--种子指标 CSV；
- 比较、bootstrap、Holm 校正、失败和完成矩阵 CSV/JSON；
- 门控汇总（不是未压缩逐原点数组）、图表源 CSV/JSON 和最终 PNG/PDF；
- `claim_evidence_map.csv`，将每个论文数字连到一行冻结产物；
- `SHA256SUMS.json`、文件数量、总字节数与验证日志。

每次复制、打包或删除前必须确认文件大小和修改时间稳定；有校验和时必须验证。只在外部归档
已成功校验且冻结紧凑证据完整后，才可清理可再生的原始中间物。不能删除失败、负向或不利
结果来压缩 release。

## 10. 实施阶段和放行条件

### Phase 0：预检与隔离

1. 重新记录 zhong3 的路径、Git、进程、GPU、磁盘和仓库状态。
2. 确认没有从 ace2、历史金融 release 或被禁止项目复制数据/结果。
3. 新建工作分支建议为 `sapr-mamba-v1`；在未获单独授权前不推送、不强推、不改写历史。
4. 用一个新且兼容 RTX 2080 Ti 的 Conda 环境验证 PyTorch、CUDA 与 `mamba-ssm` 的最小前向/
   反向传播。记录 `conda env export --from-history`、`pip freeze`、`nvidia-smi` 与编译器版本。

**放行条件：** 环境导入、一个最小 Mamba 反向传播和磁盘预算通过；否则只提交诊断，不开始数据
下载或训练。

### Phase 1：协议锁定与数据清单

1. 写入第 4--8 节的 JSON 配置；所有随机种子、阈值、周期、长度、模型宽度/层数、batch、
   最大 epoch、patience、学习率、调度器、统计族和技术重试规则必须是机器可读字段。
2. 完成真实来源可用性与许可证核验，生成数据源清单和精确序列 roster；质量规则只能依赖
   原始完整性，不能依赖任何模型结果。
3. 创建 `protocol.lock.json` 与初始 `SHA256SUMS.json`，再进行版本化提交；此提交是新研究的
   协议边界。提交或推送操作需遵循届时的人类授权，不能由 agent 擅自执行。

**放行条件：** 配置可解析、来源可获取、数据切分/标签规则可复算、协议哈希已记录。协议一经
运行即不可覆写；实质变更必须新建 `sapr_mamba_v2`。

### Phase 2：实现与测试

实现数据加载、因果状态特征、M0--M3/M3-shuffle、确定性/统计基线、训练、评估、打包与校验。
最低测试集必须覆盖：

- 未来值改动不会改变同一原点的 `phi_t`、门值或预测输入；
- M0 精确等于最后观测值的重复；M2 的门精确为 1；M3 门有限且位于 `(0,1)`；
- 输入/输出维度、反向传播、固定种子确定性与 CPU/GPU 基本一致性；
- 时间切分和滑窗目标不越过评估边界；缺失值不会由未来值填补；
- 保存后重载的预测一致；指标可由小型手算示例复算；
- 结果矩阵、失败记录和 checksum 对遗漏/重复任务会失败而非静默通过。

**放行条件：** 所有单元/集成测试通过，代码审查确认没有历史模型的隐式复用或未来泄漏。

### Phase 3：小型冒烟试验（不产生论文结论）

仅运行每类合成机制 5 条训练/2 条验证/3 条测试序列、1 个种子和一个最短跨度，用于验证吞吐、
显存、作业恢复、原子 manifest、图表与 audit 链路。冒烟结果放在忽略的 `results/smoke/`，
不能选择模型结构、阈值或领域；如发现设计错误，回到 Phase 1 并发布新协议版本。

**放行条件：** 输出维度、哈希、恢复流程、GPU 预算与完整性检查正常，且无协议变更需要。

### Phase 4：合成确认性运行

按冻结矩阵完成 M0--M3、M3-shuffle 及预设统计基线。优先逐模型/种子分块调度，每完成一个
稳定任务即写 manifest；不得在同一 GPU 上无控制地并发多个大训练。每日只读监控进程、GPU、
磁盘、已完成/预期单元数和错误日志。中途失败保持任务状态，按固定技术重试规则处理。

**放行条件：** 全部预期单元完成或明确记录失败；独立脚本从保存预测重算指标，且主比较的
分母与原始计划一致。

### Phase 5：真实数据运行

先冻结已取得数据和 quality report，再按域运行全部预设模型、种子、跨度和基线。不得根据
合成或早期领域结果删除来源、改状态阈值、只留有利跨度，或将 ETT 文件当作多个独立领域。

**放行条件：** 每个来源的来源/许可/哈希、切分、完成矩阵、失败矩阵和原始预测归档完整；
所有主表均可重算。

### Phase 6：独立重放、冻结与论文交接

1. 在干净进程中抽样重放每个模型--域--跨度至少一个任务，并独立重算全部紧凑指标。
2. 生成完整 release、SHA-256 清单、文件数/总字节数、分析表、图表和 claim--evidence 映射。
3. 使用独立校验脚本验证所有 checksums、结果矩阵完整性、数据/代码哈希匹配和图表源一致性。
4. 仅在上述检查通过后，向论文仓库同步紧凑 release、分析表、源数据、图表和同步记录；原始
   数组/检查点保留在核验过的外部归档并写入位置与哈希。

**放行条件：** 不存在未解释的缺失单元、checksum 失败或无法溯源的论文数字。若任何一项失败，
只报告阻塞，不用临时截图或日志替代冻结证据。

## 11. 论文交接规则

新论文只能在 Phase 6 之后书写数字性结论。Methods 逐项引用冻结配置和实现；Results 中每个
数字、CI、图、表和描述性门控陈述都需能回溯到 `claim_evidence_map.csv`。应保留完整模型矩阵、
稳定状态结果、无效机制、领域差异与失败记录。

可接受的表述是“在本计划定义的合成机制和若干公开单变量案例中观察到……”。不可使用
“普适地处理非平稳性”“因果证明门控机制”“跨领域泛化”“SOTA”“交易获利”或任何尚无匹配
证据的说法。中文论文框架先经作者确认，英文标题、引文、投稿格式和最终版式随后再处理。
