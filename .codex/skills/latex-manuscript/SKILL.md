# LaTeX Manuscript

## Core Contract

- Treat experiment outputs, saved metrics, configuration files, and verified sources as evidence; fluent prose is not evidence.
- Never invent citations, results, methods, hyperparameters, uncertainty, declarations, or submission requirements.
- Preserve uncertainty, negative results, incomplete comparisons, and the single-dataset boundary.
- Keep unpublished material local unless the user explicitly authorizes an external service and the venue permits it.
- Let accountable human authors approve scientific decisions, authorship, disclosures, and submission readiness.

## Companion Skill Routing

Use the smallest set of skills needed for the task:

- Use `$scientific-writing` for evidence provenance, consistency manifests, citation integrity, declarations, and submission-level scientific checks.
- Use `$peer-review` for a formal, read-only manuscript assessment or revision-response plan. Produce a separate report; never let review mode edit the manuscript.
- Use `$scientific-visualization` for plot design, uncertainty display, accessibility, export, or publisher-specific figure checks.
- Use `$nonstationary-mamba` for experiment execution, model behavior, dataset handling, and reproduction commands.
- Use `$tikz` for LaTeX-native architecture diagrams and `$graphviz` for DOT graphs.

Do not invoke a formal peer review during an ordinary section edit. Read the selected companion skill and only the reference files relevant to the request.

## Workflow

1. Classify the task.
   Distinguish source editing, numeric-claim work, result regeneration, figure work, formal review, reviewer-response work, and submission preparation.

2. Inspect the manuscript and worktree.
   Read `manuscript/main.tex`, the relevant section files, `manuscript/Makefile`, and `git status`. For result work, also read the responsible generator, data bundle manifest, configuration, and source CSV or JSON.

3. Identify the correct source layer.
   Use this ownership map:

   | Artifact | Role | Edit rule |
   | --- | --- | --- |
   | `manuscript/sections/*.tex` | Authored prose | Edit directly unless generated by a script |
   | Generated result sections and appendix tables | Derived LaTeX | Edit the generator or source data, then regenerate |
   | `manuscript/figures/generate_*.py` | Figure source | Edit here for data figures |
   | `manuscript/data/**/*` and `results/**/*` | Evidence and provenance | Read as source; do not rewrite to match prose |
   | `manuscript/main.pdf` and LaTeX auxiliaries | Build output | Never treat as an editable source |

4. Bind claims before writing.
   Trace every new numeric or comparative statement to an exact artifact. Record the dataset, split or evaluation scope, model, horizon, metric, aggregation, tuning status, and comparator. Read [evidence-and-consistency.md](references/evidence-and-consistency.md) for result or citation work.

5. Make the smallest coherent edit.
   Preserve citation keys, labels, notation, and established terminology. Keep the title, abstract, introduction, results, discussion, and conclusion aligned with the same evidence boundary.

6. Apply the task-specific gate.

   - For prose-only edits, verify meaning and compile.
   - For results or citations, apply the evidence and consistency gate.
   - For figures or tables, read [figures-and-tables.md](references/figures-and-tables.md).
   - For formal review, reviewer responses, or submission preparation, read [review-and-submission.md](references/review-and-submission.md).

7. Rebuild through the repository entry point.

   ```bash
   make -C manuscript pdf
   ```

   Use direct `latexmk` only when diagnosing a Makefile failure:

   ```bash
   latexmk -pdf -interaction=nonstopmode -halt-on-error manuscript/main.tex
   ```

8. Inspect the delivered artifact.
   Check material LaTeX warnings, unresolved references or citations, figure placement, clipping, text readability, and whether the PDF reflects regenerated sources.

9. Report provenance and limits.
   Name edited source files, regenerated outputs, evidence artifacts consulted, build result, material warnings, and any claim or submission issue still requiring human verification.

## Scientific Writing Rules

- Match the abstract and conclusion to completed evidence, not planned experiments.
- Describe methods as performed and results as observed; keep interpretation distinct.
- Tie every "best", "improves", or percentage claim to the completed comparison set and exact horizon aggregation.
- Do not imply statistical significance without a valid analysis and uncertainty definition.
- Keep cross-section values, units, model names, dataset names, horizons, and metric direction consistent.
- Mark missing evidence as unresolved instead of completing plausible text.
- Verify that every cited source exists and supports the specific proposition; a valid BibTeX entry alone is insufficient.
- Never insert `$scientific-writing` Markdown markers such as `[claim:C001]` into `.tex`. Keep optional audit registries as sidecars.

## Environment Rules

- Run forecasting experiments with `conda run -n mamba ...` as defined by `$nonstationary-mamba`.
- Run the dependency-free `$scientific-writing` and `$peer-review` CLIs with a Python interpreter at version 3.11 or newer. Check the interpreter first; do not assume the `mamba` experiment environment meets that requirement.
- Keep existing repository figure generators and their environment unless a dependency change is necessary.
- For `$scientific-visualization` pinned examples, prefer `uv` when available. Without `uv`, use a Conda interpreter only after checking required imports and record that the environment is not the upstream pinned snapshot.

## Build Conventions

Keep `manuscript/Makefile` as the build authority. It should provide `pdf`, `watch`, `clean`, and `distclean`, regenerate derived result sections and figures from their sources, render DOT figures when present, prefer `latexmk`, and fall back to `pdflatex` plus BibTeX.

Use `templates/Makefile` only when the manuscript has no Makefile. Do not replace a working repository-specific Makefile with the template.

## Typical Requests

- Rewrite a section while preserving its evidence and citations.
- Reconcile abstract claims with completed GLD experiments.
- Regenerate result tables or figures after a source CSV changes.
- Audit numeric consistency across results, discussion, and conclusion.
- Produce a separate pre-submission review and revision roadmap.
- Compile the manuscript and diagnose publication-affecting warnings.
